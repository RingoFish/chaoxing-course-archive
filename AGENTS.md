# Goal

Build a student-facing Chaoxing 智播课堂 course archive: discover courses available to the authenticated account, select persistent courses by platform course ID, discover published replays, preserve platform transcript timestamps, download the PPT recording, and produce exactly two final files per lecture (PPTX and DOCX). No speech model, language model, or mandatory manual slide selection.

# Current State

- Version 0.1.0-alpha.11. Node and uv lockfiles are committed. Runtime-private data belongs under ignored `local-data/`.
- Public source repository: `AlexbeatsZ/chaoxing-course-archive`, default branch `main`.
- Platform listing: `fanyalubodata.fanya.chaoxing.com/starcloud`; replay player: `psp-zelda.chaoxing.com/vri-zelda`.
- Discovery reads the authenticated course list, uses `courseinfoid` as the course identifier, and `speechid` as the replay identifier. Do not use course names as persistent keys.
- Persistent subscriptions live in each user's own `data/subscriptions.json` on a per-Fork `data` branch. GitHub Actions must not read course IDs from a Secret. Local runs read `COURSE_IDS` from `.env`.
- `data/delivery-state.enc` stores encrypted delivery receipts beside the subscription manifest. `archive-state/delivery-state.enc` is a legacy read source and is migrated on the next successful state write.
- `discover` lists course names and IDs in the terminal or Actions Summary without downloading videos. It initializes the per-Fork empty manifest when needed; `run` processes only subscribed courses. The replay worker receives entries from the private catalog generated by the subscription run.
- Unavailable subscribed course IDs and per-course lookup failures generate warnings; other courses and already discovered replays continue. The stored subscription is preserved.
- Live sample: 50-minute, 1920x1080 PPT recording with 259 transcript segments. Platform PPT image API returns null, so slide extraction from the recording is required. Automatic pipeline retained 55 distinct page images and assigned all transcript segments exactly once.
- `DELIVERY=relay` uploads encrypted PPTX/DOCX artifacts and records cloud handoff only after upload. The optional Windows relay downloads and sends through a loopback WeChat service; its local state is separate from cloud handoff receipts.
- Relay artifact downloads allow 2 hours per package; the installer gives the Windows task 4 hours total. Update existing task settings in place to preserve custom triggers and proxy launchers.
- Output names are `<course> 课件 NN.pptx` / `<course> 讲义 NN.docx`, numbered per course by date, lesson and speechId. Naming revision 2 nulls older receipts (backup `*V1`) so every delivered lecture is resent once; relay tracks `replay:kind:r2` separately. Update the Windows relay before syncing the Fork.
- A failing lecture records `failedSince` and only warns; after 7 days it is skipped. Transcript rechecks stop 7 days after the PPTX was first built.
- Implemented automatic extraction/cropping/deduplication, PPTX/DOCX generation, account/password login, browser-profile login, SMTP delivery, optional local OneBot/NapCat delivery, and encrypted GitHub delivery receipts.
- Synthetic video smoke checks cover moving cursor, A-B-A revisits, Office file structure, and transcript completeness. Real course discovery passed both locally and on GitHub Actions. A replay with an empty platform transcript exports PPTX now and records a 48-hour check for DOCX. SMTP receipt and QQ delivery still require acceptance tests.
- Never commit credentials, browser profiles, signed URLs, recordings, transcripts, generated documents, or private catalogs.

# Build / Run / Test

- `npm ci`
- `npm test`
- `uv sync --locked`
- `uv run --locked python -m unittest discover -s test -p 'test_*.py' -v`
- `node test/smoke.mjs`
- `node src/run.mjs --discover` lists courses and IDs.
- `node src/run.mjs` processes the data-branch subscription manifest.
- `node src/run.mjs --mail-test` tests SMTP only.
- `node src/run.mjs --help` lists supported operations.
- Requires existing `ffmpeg` and `ffprobe` on PATH. Do not install global programs without user approval.

# Durable Lessons

- `video-slide-extractor` is a detector, not a complete deduplicator or document exporter. Preserve separate occurrences when a slide reappears.
- Do not select a video by array index: use the explicit `type=ppt` metadata. The teacher and student cameras are separate streams.
- API timestamps are more precise than displayed text. Preserve the original values and any playback offset.
- Sharp JPEG delivery assets require metadata (`withMetadata`) for python-docx to recognize the JPEG reliably. Preserve 4:4:4 chroma for screen text.
- Distinguish persistent state read/decryption failure from no state. SMTP acknowledgement and mailbox receipt are different acceptance points.
- Course subscriptions and delivery receipts share the per-Fork `data` branch. Never create a shared upstream `data` branch containing a real student's course IDs.
- A phone login can default to a different bound institution. The school portal and the authenticated course list identify the correct institution. The course list endpoint can return a successful empty result if the page's week or signed login-name parameter is omitted.
- A replay can be playable while the transcript API still returns an empty array. Keep that replay pending, and keep early PPTX delivery receipts independently of final delivery receipts.
- GitHub Contents has returned inline state bytes inconsistent with its SHA and size. Read the state through the immutable Git blob identified by the same SHA used for updates; do not reset existing receipts.
